Research·Architecture·Vision

Agentic Engineering
Operating Environment

What a unified full-stack agent system — terminal to multiplexer to harness to governance, evals, workboard, credentials, and automation — could be on this machine. Built from four parallel research lanes over the live estate and external prior art.

The Verdict

Yes, build it — but unify the operator experience and execution lineage, not the products, repositories, databases, or trust domains. The missing center is a small protocol kernel, not another app.

01

The Verdict

There is a real, ambitious product here. It is not a monolith.

The right product is a local-first agentic engineering operating environment: one operator experience, one execution lineage, one vocabulary for identity, authority, evidence, and failure — over multiple replaceable terminals, harnesses, models, and services, with deterministic systems governing model-driven work.

SOTA models change the bottleneck. Cognition is increasingly abundant; the scarce parts are now knowing what work exists, preventing agents from colliding, constraining authority, surviving crashes and disconnects, proving what happened, comparing configurations honestly, and learning from real work without turning private transcripts into a warehouse. That is exactly the layer the local projects are already converging toward.

One distribution, many authorities. Most of the difficult domain cores already exist on this machine — the missing center is a versioned protocol kernel plus conformance suite that lets them compose safely.

The acceptance oracle

The unified system succeeds only if replaceability holds end to end:

  • Any one terminal, multiplexer, harness, credential broker, workflow engine, work ledger, eval runner, or human projection can be replaced without rewriting authoritative history.
  • A disconnect does not terminate durable work.
  • An observation outage never gains control authority.
  • A credential outage fails closed, with no raw-secret fallback.
  • An ambiguous external effect is never blindly retried.
  • No component reads another component's private database.
  • The system stays useful from plain CLI tools when the unified UI is gone.

Explicit non-goals

No shared mega-database. No universal workflow DSL. No transcript warehouse. No premature top-level product pick. No merging of trust domains to make a dashboard prettier.

Data, control, and evidence are different planes

DATA What flowed

PTY bytes, model streams, tool output, artifacts, and external responses. Private by default. Never a cross-system control bus.

CONTROL What changed

Claims, grants, launches, transitions, approvals, budgets, cancellation, and effect requests. Every mutable fact has one owner.

EVIDENCE What was observed

Immutable observations and receipts. A Feed row, event, trace, or model claim does not become proof merely by being stored.

An Overmind outage must not stop work. A Powder event does not become a workflow transition because it appeared in the Feed. A Crucible result is evidence, not authority, unless a Bitterblossom workflow explicitly declares a deterministic gate. Mint enforces custody and mechanical policy; it does not decide whether an operation is semantically appropriate.

04

The Small Stable Kernel

Begin with schemas, validation rules, fixtures, and adapter conformance tests — not another daemon.

The kernel contains only the cross-system facts needed for safe handoff and correlation. Domain semantics stay inside deep owners: panes in Herdr, execution in the harness, transitions in Bitterblossom, work in Powder, custody in Mint, measurement in Crucible, and projection in Overmind.

05

Build vs Integrate

Own the control contracts and the learning loop. Rent or reuse the undifferentiated substrate.

Ghostty DO NOT REWRITE

Keep the daily terminal. A future shell may embed libghostty-vt, but only after the higher-level data models stabilize. Rendering is not the current bottleneck.

Herdr KEEP

Build against its structured API rather than parsing screen contents. A future native UI can use Herdr as an out-of-process session backend and remain restartable.

OMP PRIMARY

Do not migrate on aesthetics. The integrated editing, language intelligence, debugging, subagents, schemas, and tools would be expensive to recreate.

Pi ADD + MEASURE

Implement the same harness adapter for Pi. Let Crucible compare real task outcomes. Migrate individual lanes if Pi wins; no wholesale cutover is required.

Domain services KEEP SEPARATE

Powder, Bitterblossom, Mint, Crucible, Canary, and Overmind have different trust domains, retention policies, write authorities, and failure modes. One distribution can still make them feel like one product.

Native shell LATER

Build it only after the APIs prove themselves in shadow mode. The UI must be a replaceable face over public contracts, never the process owner or hidden state store.

The OMP versus Pi decision

Make this an experiment, not a religion. Run the same task families through the same composition, worktree, sandbox, budget, and result schema. Compare success, edit correctness, recovery, instruction adherence, cost, context use, operator interventions, and adapter breakage. If Pi wins one task family, migrate that family. OMP can remain the interactive primary while Pi handles bounded unattended work.

The missing execution boundary

Worktrees separate edits; they do not isolate processes or networks. Unattended operation needs a declared sandbox with writable roots, network deny-by-default, brokered egress, and honest attestation of what the adapter can enforce. Mint contains credentials, not the entire filesystem or network.

06

The First Experiments

Build falsifiable vertical slices. Each one either reduces uncertainty or kills an attractive but wrong direction.

1

Correlation spine

Add one root trace ID and typed cross-references across Powder, Bitterblossom, the harness, Herdr metadata, Mint audit, Canary, Crucible, and Overmind — without changing behavior.

PASS · From any ID, reach every related owner record without database access or manual string matching.
FAIL · A central database becomes necessary, or one component must inspect another's private store.
2

Card-to-proof golden path

One real Powder card is accepted idempotently by Bitterblossom, claimed, resolved to a pinned composition, launched through an adapter into a Herdr worktree, executed by OMP under declared limits, and completed with typed proof. External operations use Mint-backed named effects.

PASS · No duplicate claim, model call, commit, comment, or effect. No secret enters the child environment. Kill-and-resume produces one explainable outcome.
FAIL · The path still relies on prose parsing, shell glue, manual IDs, or blind retry.
3

OMP versus Pi tournament

Run representative tasks across both harnesses with identical launch contracts, repository snapshots, tools, sandbox, budget, output schema, and graders. Crucible changes only the harness axis.

PASS FOR PI · Non-inferior outcomes, typed results, recovery, cost visibility, sandbox enforcement, and maintainable adapters across upgrades.
FAIL FOR MIGRATION · Pi's smaller core forces reconstruction of OMP's editing, LSP, debugger, subagent, or tool semantics.
4

Failure campaign

Deliberately trigger terminal disconnect, Herdr restart, UI crash, harness crash after a paid response, Bitterblossom restart mid-step, Mint outage, prepared-without-terminal audit, ambiguous GitHub effect, Powder lease expiry, Overmind outage, and unavailable optional eval gate.

PASS · Work resumes safely or stops in a named recoverable state. Observation failure never grants authority. Credential failure has no direct fallback.
FAIL · “Unknown” is treated as success, zero, or permission to retry.
5

Native-shell shadow mode

Prototype one read-only screen with workspace and agent list, active terminal, acceptance criteria, authority, budget, structured timeline, approval queue, evidence, and eval verdicts. Run beside Ghostty and Herdr.

BUILD · It materially reduces time spent locating state, switching tools, diagnosing blocks, or steering concurrent work.
ABANDON UI · The operator keeps returning to raw Ghostty. Preserve the protocol work and delete the shell.
07

The Learning Flywheel

The durable advantage is not the UI. It is a private, evidence-backed loop from real work to better execution policy.

real work→ bounded trajectory→ redacted corpus→ Crucible comparison→ evidence-backed policy→ pinned composition ↺ new real work

This turns model and prompt selection from taste into measured engineering. Every production task can improve the system, while raw proprietary output remains owner-local and bounded.

Task-family routing

Select models by demonstrated performance on the kind of work actually being attempted, not by global leaderboard.

Configuration qualification

Evaluate role, skill, tool, rule, and harness changes before rollout. Attribute one changed axis at a time.

Counterfactual replay

Replay one failed or expensive run with another model, tool set, reviewer team, or harness and measure which change helped.

Complementary teams

Pick reviewers based on measured disagreement and defect catch patterns rather than using the same model family twice.

Cost versus success

Optimize for verified outcomes per dollar and operator intervention, not token price in isolation.

Gradual autonomy

Promote workflows from supervised to unattended only after recorded evidence supports the authority increase.

Do not let the system auto-promote itself from a noisy comparison. Crucible's confidence, calibration, and trust transitions remain load-bearing.
08

What Opens Up

Once the spine works, the machine stops being a collection of chats and becomes a software-defined engineering organization.

01 Durable campaigns

Cross-session, cross-agent work continues through disconnects, reboots, and model changes without replaying paid completed steps.

02 On-demand teams

A card compiles into architect, builder, reviewers, verifier, and incident investigator with separate models, tools, grants, and worktrees.

03 Safe external action

Agents deploy, open pull requests, update ledgers, and interact with production without ever possessing transferable vendor credentials.

04 Incident-to-fix loops

Canary incident → Bitterblossom responder → Powder card → isolated run → proof → review → deployment → Canary readback.

05 Harness portability

One composition runs through OMP, Pi, Codex, Claude, or a remote sandbox without changing work, authority, or evidence contracts.

06 Counterfactual engineering

Replay a real failure under controlled changes and know whether the model, prompt, tool, sandbox, or reviewer altered the outcome.

07 Mobile mission control

Overmind and Powder expose bounded status and approvals while source code, terminal streams, and credentials remain local.

08 Governed maintenance

Dependency updates, flaky tests, documentation drift, incident follow-up, and backlog hygiene run continuously under leases and proof gates.

09 Replaceable model market

Models become interchangeable cognitive engines, selected by evidence rather than architectural dependency or vendor habit.

∞ Self-measuring organization

The system gets better through evidence from its own work — not prompt folklore, marketing claims, or one benchmark score.

Current Hazards

These gaps matter more than starting a new UI or replacing a terminal.

HIGH

No common lineage. Powder card IDs, Bitterblossom runs, harness sessions, Herdr panes, Mint effect IDs, Crucible runs, Canary incidents, and Overmind rows require manual joins.

HIGH

Workflow authority is ahead of implementation. Bitterblossom's target describes typed effects, approvals, and waits, but the shipped new WorkflowDoc runtime executes agent steps only. Draft lifecycle workflows can look more executable than they are.

HIGH

No unified sandbox. Worktrees separate Git changes, not process privileges or networks. OMP skill visibility is not an authority boundary, and “yolo” execution is unsuitable for unattended external effects.

HIGH

Credential adoption remains incomplete. Bitterblossom has a parked direct Powder path; Overmind's GitHub watcher reads GITHUB_TOKEN or gh auth token outside Mint's adoption inventory.

MEDIUM

Shared Powder credential alias. Multiple consumers use one alias, making rotation, revocation, and incident blast radius coarser than the worker identities suggest.

MEDIUM

Mint self-health telemetry is noisy. The live broker is healthy and the Roster credential retirement passed its zero-disclosure probe, but Mint's tag:server Canary event receives HTTP 422 and temporarily appears as an unresolved prepared effect. Powder card mint-998 owns the separate contract repair.

MEDIUM

Three human queues. Powder request/input, Bitterblossom asks, and Crucible adjudication all need human judgment. Unify their projection, not their native semantics or writeback.

MEDIUM

Vision exceeds shipped behavior. Overmind's Vision describes automation and authority; its current README and doctor say observation-only. Several other product docs similarly lag or lead the code.

MEDIUM

Raw terminal data is already persistent. Local multiplexer configuration captures pane content. Copying raw ANSI or full transcripts into Overmind or Crucible would enlarge the disclosure and retention domain.

MEDIUM

Audit IDs are isolated. Mint, Powder, and Overmind each hold independent append-only records without a shared correlation envelope, making incident forensics manual.

LOW

Double narration. If Powder events feed Overmind while agents also post milestones, the same work may appear twice unless correlation and deduplication are explicit.
